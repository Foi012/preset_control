# 变量宏：行为与呈现设计

状态：2026-10-21 已实现核心行为与 UI；嵌套变量／简写等未支持项保留原文并诊断。原生边界对照和逻辑／隔离 UI 检查通过，真实 ST 人工验收待进行。

## 收敛后的预览范围

采用原生条目顺序与 marker 占位，不启动完整隐藏 ST 实例。
char/user 等上下文宏保留字面形式。计算 setvar/getvar/addvar 及对应 global 宏，追踪变量贡献来源。
非预设正文不在工作台展示；此视图是预设文本与变量结果预览，不声称包含 token 裁剪或第三方请求变换。

## 已核对的行为

资料：

- https://docs.sillytavern.app/usage/core-concepts/macros/
- https://docs.sillytavern.app/usage/st-script/
- 安装版本的 `public/scripts/variables.js`（getVariableMacros、addLocalVariable、addGlobalVariable）
- 安装版本的 `public/scripts/macros/definitions/variable-macros.js`（新宏引擎注册定义）

`{{addvar::name::value}}` 修改当前聊天变量，不直接输出文字；`getvar` 才输出当前值。
`addglobalvar` 行为相同，作用域为全局变量。不要与 `/addvar` 斜杠命令的管道输出混为一谈。

本机原生函数在独立 Node VM 中验证的结果：

| 已有值 | add 参数 | 保存后的值 | 呈现语义 |
| --- | --- | --- | --- |
| `10` | `2` | 数字 12 | 加 2；10 → 12 |
| `001` | `2` | 数字 3 | 按数值计算，不保留数字字符串格式 |
| `保持简洁。` | `避免重复。` | `保持简洁。避免重复。` | 追加文字；不会自动插入分隔符 |
| `["A"]` | `B` | `["A","B"]` | 加入一个数组项 |
| `[]` | `2` | `["2"]` | 宏参数作为数组元素保存为字符串，不推测为数字 |
| 未定义 | `提示文本` | `提示文本` | 从默认初值开始；标注无前置定义 |
| `0` | `提示文本` | `提示文本` | 原生 falsy/类型转换行为，不能自行实现成 `0提示文本` |

以上是具体本机版本行为；不得把所有 add 都实现为拼接或数值加法。

## 以正文为中心的呈现

例子使用三个独立条目，避免隐含同一条目内的宏替换次序：

1. 基础规则：`{{setvar::rules::保持简洁。}}`
2. 补充规则：`{{addvar::rules::避免重复。}}`
3. 正文模板：`{{getvar::rules}}`

全部条目视图中，第一个条目正文是「保持简洁。」，第二个是「避免重复。」；
小号身份说明分别为「设置 rules」「追加到 rules」。不能因为写入宏输出为空而隐藏条目，
也不能在追加条目里默认重复显示整份累计结果。一个条目混有普通正文和变量操作时两者都保留。

读取位置显示最终正文「保持简洁。避免重复。」。平时为连续文本，悬停／点击贡献片段才显示来源与编辑入口。
初始片段归基础规则，追加片段归补充规则；不要只保留最后写入者。
char/user 等字面宏仍原样显示，不代入名字。

数值输出如「12」不能按字符拆分贡献。点击后在现有关联侧栏显示：

- 基础分数：设置为 10。
- 加成规则：增加 2，10 → 12。
- 正文模板：读取 12。

数组在读取处保持原生 getvar 的 JSON 文本，关联侧栏按项显示来源（可按需展开），
不要为了看起来友好将数组静默改为自然语言列表。

## 关联面板表达实际作用

沿用条目侧栏固定的“编辑／当前读取的值／其他关联”三个区域，不为每项创建手风琴或额外面板。

- 当前值：显示此次读取位置的值，而非整个预设执行完后的统一最终值。
- 值的形成：按实际计算次序展示设置、追加／增加／加入项和覆盖，含所属条目。
- 读取位置：列出使用该值的后续输出，可定位并重新预览。
- 其他同变量条目：OFF、未放置和不参与当前值的候选，作为次要内容收起；不冒充依赖。
- 名称为普通文本，查看条目／编辑／加入选择为明确动作；复用现有控件语义与两行顶部布局。

后续 set 会覆盖旧累计值：当前输出来源链从最近有效 set 重新开始，旧定义仍可在「其他同变量条目」中查看；当前未实现完整覆盖历史时间线。
纯数值计算保留整条贡献链；字符串累计保留片段来源；数组保留各项来源。
局部与全局变量不能因为同名混到一条链中。

关闭条目保留其原始追加内容，标注未参与；试开后重新计算。多个 add 通常是可组合贡献，
不能自动推断为互斥。同变量关系本身既不是必需依赖，也不是分组规则。

## 编辑与复制

编辑文字片段时修改其来源条目的原始宏参数；保留原文、标点、换行与宏表达式。
累计结果只读，避免把 getvar 改成常量或把其他贡献覆盖进最后一个 add。
数值结果点击后选择需要调整的设置或增量；不能把输出结果直接当作最后一个增量。

复制 add 条目时明确列出此前设置／贡献及后续读取位置，让用户选择是否携带，
不自动带走所有同变量条目。目标已有同变量值时，按真实插入点展示预计前值 → 后值和受影响读取位置。

## 计算与测试约束

- 每次预览从同一份初始变量快照重新计算，不能在上一次预览结果上再次 add。
- 无预设内初始化时，注明来自当前聊天／全局变量快照；无已知值时记录原生默认行为。
  非预设正文被占位，意味着其潜在变量写入不自动得到模拟；遇到这种依赖需注明上下文来源未知。
- 不直接调用会持久化的 ST set/add 函数；预览变量属于隔离副本。
- 兼容当前 ST 的宏引擎设置。legacy 是按宏类别多轮替换，不能统一简化成从左往右。
  已验证同一条目 `{{setvar::n::1}}{{getvar::n}}|{{addvar::n::2}}{{getvar::n}}` 在本机 legacy 下得到 `3|3`。
- 新宏引擎支持嵌套与不同的替换规则。嵌套、注释、未知宏、无法证明的结果应保留原文／说明不支持，不能伪造准确输出。
- 不用简单正则把 `{{char}}` 内的右括号误当作外层 set/add 的终点。
- 断言应包含数值、字符串、数组、未定义、0、数字字符串、分隔符、多次追加、覆盖后来源重置、多个读取时刻、OFF 隔离、作用域隔离、重复预览不累加、无真实变量写入。
- 使用精简构造样例，原生语义对照使用当前安装 ST 源码的纯变量函数，不复制私人预设。
